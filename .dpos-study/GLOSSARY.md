# GLOSSARY — нотация корпуса и термины, которые заметки употребляют неодинаково

Формат: термин — что это ЕСТЬ; `_Избегать_:` синонимы, встреченные в корпусе. Только специфичное для этого проекта. Если термин определён в `.claude/dpos_architecture/`, здесь одна строка и ссылка на секцию (архитектура живёт там, здесь не пересказывается).

## §1 Нотация

- **R-nnn** — запись реестра находок узла (`REGISTER.md` §1; R-001..R-123). R-101..R-110 — расхождения границы узел↔контракт; R-111..R-113 — инцидент пола; R-114..R-119 — дубли; R-120 — принятый риск, не дефект. `_Избегать_:` «находка №n» без префикса.
- **K-n** (латинская K) — находка аудита контракта (`REGISTER.md` §2; K-1..K-40). **К-n** (кириллическая К) — вопрос к контракту из `history/REGISTER.md` часть 4 (К-1..К-13, все закрыты 09-03). Различаются алфавитом — при чтении проверять контекст. `_Избегать_:` смешение K/К.
- **КB-n** — упрощение контракта из `history/AUDIT-CONTRACT.md` часть B (там они названы B-0..B-7; префикс `К` добавлен в PLAN, чтобы не путать с AUDIT B-n). `_Избегать_:` «B-n» применительно к контракту.
- **B-n / BB-n / CB-n** — упрощения из AUDIT / AUDIT-BEACON / AUDIT-CORE (`REGISTER.md` §3). **A-n / BA-n / C-nn** — исходные находки тех же трёх аудитов, сведены в R (`REGISTER.md` §4). `_Избегать_:` «BA» для beacon-упрощений (это BB).
- **Д-n** — решение (`DECISIONS.md` §1; Д-1..Д-13). В `history/REDESIGN.md` часть 1 «Д-1..Д-10» — ДИАГНОЗЫ структуры кода, не решения; в живом слое они не нумеруются и называются «диагноз REDESIGN n». `_Избегать_:` ссылка «Д-4» без уточнения, откуда — решение и диагноз с одним номером означают разное.
- **П-n** — предложение перестройки из `history/REDESIGN.md` (`DECISIONS.md` §2; П-1..П-10).
- **Э0..Э8** (без дефиса) — этапы плана (`PLAN.md` §2). **Ex-n** — эксперимент (`EXPERIMENTS.md`; бывшее «Э-n» с дефисом из EXPERIMENTS/REGISTER часть 5). Выбор 2026-09-09: эксперименты — `Ex-n`, этапы — `Эn`. `_Избегать_:` «Э-n» для экспериментов, «Э-2» в смысле «этап 2».
- **E1..E5** (латинская E) — пять прогонов инцидента пола 09-04 (`EXPERIMENTS.md` §1); не путать с этапом Э1 и с признаком завершения «E1/E2/E5 живут» в старом `PLAN.md` (те же прогоны). **E-n** с дефисом — расхождения doc-комментариев с кодом в `history/AUDIT-CORE.md` часть E.
- **F-номера** — три несовместимых ряда: `F1..F10` — находки закрытия Э1 (`history/E1-CLOSEOUT.md`); `F-1..F-17` — находки работы 1.8 (`history/E1-8-TESTS.md`); `F-1..F-13` — расхождения с UNDERSTANDING в `history/AUDIT-CORE.md` часть F. **Ф-n** — находки Э2 (`history/E2-ABI.md`). При ссылке всегда называть документ.
- **D-n** — эмпирические вопросы аудитов (`history/AUDIT*.md` часть D, `history/AUDIT-CONTRACT.md` часть D); **D1..D12** — расхождения записи и кода в `history/E1-REFLECTION.md` §4. **X1..X10** — столкновения работ Э1 (там же §2). **Rn.m** — остатки работы n.m (там же §1). **W-n / G-n** — «стало хуже» / «в порядке» (там же §5–§6).
- **M-n, C1..C5, E1, EM1..EM3** — мутации контракта/e2e в `history/E1-8-TESTS.md` (C-n здесь — комбинированные мутации, не находки AUDIT-CORE).
- **T-n** — тесты как ложная уверенность (`history/AUDIT-CONTRACT.md` часть T). **V-1..V-22** — вердикты по §15 `history/CONTRACT-UNDERSTANDING.md` в `history/AUDIT-CONTRACT.md` части V; трассировка — `REGISTER.md` §4, семь из них («не дефект») своего номера K не получили. **N-1..N-3** — дешёвые пункты очереди (`EXPERIMENTS.md` §3). **G-n / L-n** — оффлайн / живые группы `agreement_check.py`.
- **Столбец «Как»** (INDEX 09-04): `С` — закрывается структурной работой без отдельной правки; `С+` — структурно смягчается, остаток назван; `П` — поштучная правка; `—` — не трогать. **Коробки**: `[x]` сделано, `[~]` решение принято или часть кода есть, `[ ]` открыто, `[-]` отменено.
- **Теги уверенности**: `[KNOWN]` — файл открыт или команда выполнена в ТОЙ сессии, что писала; `[LIKELY]` — из документа, не перечитано; `[GUESS]`/`[ГИПОТЕЗА]` — вывод; `[LOOKUP]` — не проверялось; «эксперимент+/−» — подтверждено / не воспроизвелось на стенде; «по записи» — пересказ чужого прогона. **«ВЕРА»** — допущение о контракте, снятое после появления исходников 09-03.
- **Дерево A / B / C** — `~/Work/audit-482/pr482-study` (worktree контракта, история с 09-09) / `~/Work/fluentbase` (узел; с 09-09 и контракт) / `~/Work/solidity-contracts` (солидити, источник верификатора). `_Избегать_:` «дерево контракта» без буквы.
- **Пути без префикса** в записях реестра — от `crates/dpos/consensus/src/`; `node/` = `crates/node/src/`; `CW:` — commonware checkout; `RETH:` — reth checkout; контракт — `contracts/staking/src/`.

## §2 Термины проекта

- **пол (комитета)** — `MIN_COMMITTEE_LENGTH = 4`, наименьшее n с f ≥ 1; ниже пола `commitEpochCommittee` ревёртит `CommitteeTooSmall`, и цепь останавливается (решение 1.0). Константа в `.claude/dpos_architecture/12_consensus_critical_constants.md`. `_Избегать_:` «минимум комитета», «floor» без уточнения — «floor» в узле также значит нижнюю границу ретенции (`retain_floor`, `set_floor` marshal, `floor_hash` в `reseed_forward`).
- **потолок (cap)** — `activeValidatorsLength` ∈ [4, 51] (`MAX_COMMITTEE_SIZE` общий с 09-09); комитет = верхние `cap` по стейку среди пригодных. `_Избегать_:` «лимит», «cap-чекпойнт» (удалены 1.1).
- **популяция / селекционно-видимые** — валидаторы, из которых отбирается комитет: ACTIVE, не отстранены, не помечены, с консенсусным ключом на эпоху. Штамп видимости (`set_selection_visible`) пишут пять писателей; floor-проверка есть ровно у одного (`apply_production_exclusion`), и та против потолка, а не против `MIN_COMMITTEE_LENGTH` (R-113). `_Избегать_:` «реестр» в этом смысле (реестр — `getRegistryWithKeys`, набор пиров).
- **эпоха отбора** — `target − MAX_COMMITTEE_LOOKAHEAD_EPOCHS` (E−2): комитет эпохи E решается из состояния E−2 и замораживается; с 1.9 по тому же снимку делятся доли делегаторов и берётся ставка. Лидер/leader schedule — `03_epoch_machinery.md` §3.4. `_Избегать_:` «эпоха выбора», «selection epoch» в смысле «эпоха, где выбирают».
- **перенос комитета (carry-over)** — удалённый механизм (Э0.2 → отменён 1.0): при недоборе переиспользовать запись `target−1` с `dkgQual=false`. В коде и `dpos_architecture` не должен описываться как живой. `_Избегать_:` «пересадка» (это штатный отбор нового комитета без выбывшего — противоположное), «carry-forward» (это про КЛЮЧ, см. ниже).
- **carry-forward ключа** — ключ эпохи `PK_E` наследуется от последней эпохи с `dkgQual=true`; узел находит её сканом `chain_key_epoch` (`beacon/carry.rs`, уходит с П-3). `_Избегать_:` «перенос ключа» рядом с «переносом комитета».
- **dkgQual** — бит контракта «комитет сменился на этой эпохе» (не «DKG удался»); узел выводит его сам сравнением ростеров (Д-7). `_Избегать_:` «qualified».
- **тумбстоун** — необратимый флаг `tombstoned` в контракте после эквивокации; узел рвёт транспорт и отказывает лидеру по флагу, но НЕ вычёркивает место из комитета (знаменатель кворума не меняется). `07_slashing_end_to_end.md` §7.2. `_Избегать_:` «джейл» как синоним (JAIL — статус, тумбстоун — флаг; ставятся вместе, но читаются разными потребителями), «бан».
- **маршрут улик / системный маршрут** — два пути слэшинга: permissionless `slashEquivocation{Notarize,Finalize,NullifyFinalize}(bytes…)` с уликой, проверяемой контрактом; системный `slashEquivocation(epoch, signerIdx)` из предысполнения по вердикту комитета. Решение Д-4. `_Избегать_:` «транзакционный маршрут» (это узловая сторона того же — WAL, `enqueue_fallback`), «in-block charge» (это заряд системного маршрута).
- **заряд (charge)** — улика эквивокации, которую лидер вкладывает в блок (`extra_data.accused`), а комитет проверяет при голосовании; живёт до конца своей эпохи. `_Избегать_:` «обвинение», «evidence» в этом смысле.
- **предысполнение (pre-execution) / системный вызов** — три вызова контракта из узла до транзакций блока: `recordProduction`, `commitEpochCommittee` (fail-loud: ревёрт = ошибка исполнения блока у всех узлов сразу), `slashEquivocation` (мягкий: warn + счётчик). Бюджет 30 000 000 газа. `08_node_integration…`. `_Избегать_:` «syscall-транзакция», «логи системного вызова становятся чеками» (не становятся).
- **fail-loud / мягкая диспозиция** — как узел обрабатывает ревёрт системного вызова: `Corruption` ⇒ abort-all у всех узлов (fail-loud) против пропуска с метрикой. `_Избегать_:` «фатальный/нефатальный ревёрт».
- **Corruption** — класс `Fault` по умолчанию для нетипизированной ошибки (`From<eyre::Report>`); ведёт в `Shutdown` executor и abort-all `OuterEngine`. `_Избегать_:` «порча состояния» (это не про диск).
- **SafetyHalt** — защёлка форк-безопасности: узел паркуется с удержанием ack навсегда, маркер на диске. `09_followers.md` §9.6.2. `_Избегать_:` «halt» для остановки на полу (та — `Corruption`, не защёлка).
- **result-gate** — проверка при голосовании, что `OrderBlock.result` для высоты h равен EVM-хэшу блока h−K; poll 41×25 мс внутри `verify`. `02_ordering_core…` §2.3. `_Избегать_:` «гейт результата», «guard #1».
- **guard #2** — постусловная проверка executor'а на пути догона: сравнение `result` с `spec_executed_hash`; читает канонический хэш reth до FCU (R-006). `02_ordering_core…` §2.4. `_Избегать_:` «второй гейт».
- **K** — лаг deferred execution (= 3): блок h несёт результат h−K. `_Избегать_:` «K» как размер комитета.
- **спекуляция (spec_exec)** — исполнение нотаризованного, ещё не финализированного блока; спекулятивный FCU канонизирует его. `_Избегать_:` «оптимистичное исполнение».
- **удержание (hold) / `awaiting_seed`** — executor не выдаёт финализацию, пока нет σ её раунда; выход — `seed_edge` или re-jump. `_Избегать_:` «зависание».
- **σ (seed)** — пороговая BLS-подпись раунда, едет в сертификате финализации (хвост `seed_flag ‖ σ`), потребители — VRF лидера и `prev_randao`. `_Избегать_:` «сид блока» (поле из тела блока удалено, FLU-1204).
- **PK_E / артефакт / share** — ключ эпохи из DKG; `AgreedArtifact` — единственный факт с подписью кворума; share — доля узла (share-файл). `05_identity_crypto.md`, `03_epoch_machinery.md` §3.3. `_Избегать_:` «mint» как синоним ключа (mint — запись `CeremonyStore`, одно из пяти представлений).
- **лог dealer'а** — `SignedDealerLog`; идентифицируется сейчас по dealer'у, с П-9 — по `(dealer, hash)`. Эквивокация лога — R-002. `_Избегать_:` «дилинг» (одно сообщение внутри лога).
- **Torn / NoFile** — состояния журнала DKG при старте: нечитаемая запись ⇒ сидеть вне эпохи; отсутствие файла ⇒ `start_fresh` (после дедлайна — честная эквивокация лога, R-036).
- **recompute-heal** — восстановление share из журналов пиров после пропуска; окно — 1 эпоха (`JOURNAL_RETENTION_EPOCHS`).
- **agreement-плоскость / вторая simplex-плоскость** — отдельный инстанс simplex с собственным namespace для согласования артефакта ключа (`dkg_engine.rs`). `_Избегать_:` «DKG-консенсус».
- **фронтир** — «финализированный фронтир сети»: пять определений в коде (пробa `Latest`, `upstream_frontier`, `corroborate_frontier`, backfill, replay), три неаутентифицированы (R-001/R-003/R-004/R-009); П-4 сводит к одному `Frontier`. `09_followers.md` §9.6.1 (`CertUpstream`). `_Избегать_:` «tip» (marshal tip — одно из определений).
- **прыжок (jump) / cold start / re-jump** — синхронизация reth к фронтиру с последующей аутентификацией; cold start — при запуске (`ColdStartKind`, `04_cold_start…` §4.1), re-jump — в работе при отставании > порога `min(1024, interval)`; self-heal — `04` §4.3.1. `_Избегать_:` «догон» для прыжка (догон — последовательный backfill), «холодный старт» для crash-recovery.
- **backfill / gap-repair / `hint_finalized`** — marshal подтягивает пропущенные высоты по `Finalized{h}`; `deliver` — вердикт резолвера; `hint_finalized` — подсказка, что финализация есть. `09_followers.md` §9.6.
- **upstream / follower / inlet** — источник сертификатов для follower'а (WS `--cert-follow` или plane-native); follower — узел без ключа подписи; `CertInlet` — его приёмник. `09_followers.md`. `_Избегать_:` «реплика», «light client».
- **vote-only admission / verify-only** — сертификат принят без проверки σ (нет ключа) / узел без share сидит в эпохе не подписывая. `_Избегать_:` смешение двух.
- **primary / secondary / реестр (Active)** — `TrackedPeers` commonware: primary буферизуется broadcast'ом; сегодня primary = реестр ∪ два комитета; реестр = `getRegistryWithKeys` (только Active, наполняет governance — К-7). `05_identity_crypto.md`. `_Избегать_:` «peer set» без уточнения.
- **BiMap / `Participant`** — индекс участника = позиция в отсортированном по байтам наборе ed25519-ключей; общий с сортировкой контракта (группа 2 дублей, R-116). `_Избегать_:` «signer index» как независимая величина.
- **namespace** — база подписи `FLUENT_DPOS_V1_ ‖ chain_id`, суффиксы `_NOTARIZE/_NULLIFY/_FINALIZE/_SEED` добавляет commonware; контракт собирает вручную (R-115, группа 1). `_Избегать_:` «домен» (DST — другое: домен hash-to-curve).
- **PoP** — proof-of-possession BLS-ключа при `registerValidator`; с 1.10 проверяется инлайн контрактом против предеплоев EIP-2537 (`0x02/0x05/0x0b/0x0f/0x10`). `_Избегать_:` «внешний верификатор» (удалён).
- **предеплои** — rWasm-контракты по фиксированным адресам (EIP-2537 и SHA-256), ставятся генезисом, обновляемы через `runtime-upgrade`; считают BLS через arkworks, узел подписывает через blst. `_Избегать_:` «прекомпайлы» в смысле встроенных.
- **стипендия / пот / резерв / форфейт** — BLEND-награда за эпоху (`setBlendStipendPerEpoch`); пот — сумма эпохи; резерв — внешний адрес, с которого платят `transferFrom` (Д-10); форфейт — эпоха закрыта нулём навсегда, если `min(balanceOf, allowance)` < пота. `_Избегать_:` «фонд» (фонд — `slashFund`, получатель конфискаций), «долг/отсрочка» (удалены с курсором).
- **претензия (claim) / тело (principal) / комиссия** — `claimValidatorFee` (беспермиссионная, платит владельцу), `claimDelegatorFee` (только награда с 1.7), `withdrawDelegatorPrincipal` (тело с баланса контракта). `_Избегать_:` «вывод награды» для тела.
- **лестница (kick ladder) / исключение** — liveness: провалившего производство исключают из отбора на `duration` по `kick_count`; сброс через 30 эпох с последнего провала (`KICK_LADDER_RESET_EPOCHS`, работа 1.9в; Д-13). Лестница — `07_slashing_end_to_end.md` §7.1; сброса там нет — дрейф, `PLAN.md` §1. `_Избегать_:` «бэкофф» без «лестница».
- **геометрия эпох** — пара (`dposActivationBlock`, `epochBlockInterval`); узел морозит при первом чтении, контракт запрещает менять после активации (R-101 — окно до активации). `06_staking_layer.md` §6.3. `_Избегать_:` «параметры эпохи».
- **блоб / `STAKING_ARTEFACT.md` / голден** — собранный `.wasm`/`.rwasm` контракта (gitignored, вендорится руками); документ с дайджестами и ритуалом сборки; голден смоука — снимок, инвалидируемый только по id образа. `_Избегать_:` «артефакт» без уточнения (артефакт DKG — другое).
- **смоук / кейс / стенд xp / sim / prod-стек** — `make smoke-*` кейсы харнесса (`dpos_harness`); `scripts/xp/` — стенд на N узлов без вердиктов; sim — стохастический churn с гейтом; prod-стек — 6/5 с runtime-деплоем и `forge`. `EXPERIMENTS.md` §4. **стенд в крейте / testbed** — `crates/dpos/consensus/src/testbed/` (`#[cfg(test)]`, N узлов `OuterEngine` в одном процессе на `commonware_runtime::deterministic` + simulated p2p, виртуальное время; с 09-09, `history/E3-2-STAND-1.md`). `_Избегать_:` «эксперимент» для смоука; «стенд» без уточнения, какой из трёх.
- **заглушка честная / вакуумный тест / анти-вакуум / tripwire** — заглушка, умеющая отказать; тест, который не выполняет названный путь; ассерция, доказывающая, что предпосылка достигнута; негатив, который не может упасть, но задокументирован. Критерий Д-12.
- **conformance-набор / `FakeDeriver`** — тесты трейтов reth (`BeaconEngineLike` и др.) против фейка и in-process reth (Э3.1); `FakeDeriver` канонизирует при derive, чего reth не делает (R-006). `_Избегать_:` «интеграционные тесты» для conformance.
- **дрейф (doc-drift)** — расхождение `dpos_architecture`/комментариев кода с кодом; по CLAUDE.md — блокер ревью. Живой список — `PLAN.md` §1.
- **«наполовину»** — что случится, если применить предложение частично (обязательное поле П-записей и журналов работ).
