# .dpos-study — рабочие заметки по crates/dpos и стейкинг-контракту

Два слоя. **Живой слой** — шесть файлов в корне: `README.md` (этот), `PLAN.md`, `REGISTER.md`, `DECISIONS.md`, `EXPERIMENTS.md`, `GLOSSARY.md`; в них только текущее состояние. **Архив** — `history/` — 26 оригиналов дословно (2026-09-03 … 09-09) плюс `history/README.md` с картой архива и трассировкой каждого раздела; консолидация описана в `CONSOLIDATION-REPORT.md`. Правило: **`history/` — не свидетельство текущего состояния** (там четыре шапки называют worktree, который перестал быть каноническим 09-09, дайджесты блоба, устаревшие дважды, и статусы, отменённые позже); факт живёт ровно в одном живом файле, остальные на него ссылаются. Архитектура узла и контракта — только `.claude/dpos_architecture/` (сначала `TOC.md`); живой слой на неё указывает, не пересказывает. Что даёт `git log`, код и `dpos_architecture`, живой слой не кэширует.

## Как поддерживать

- Закрыл работу — одна строка статуса в `PLAN.md` §2 (сделано — sha / идёт / открыто / отложено); цифры ворот с датой — `PLAN.md` §1.
- Изменился статус находки — только `REGISTER.md` (одна форма статуса и источник); в `PLAN.md` не дублировать.
- Принял или снял решение — запись в `DECISIONS.md` со строкой статуса и датой; `PLAN.md` §5 только ссылается.
- Провёл эксперимент — строка в `EXPERIMENTS.md` §1 или §2; очередь §3 подвинуть.
- Журнал этапа — новый файл в `history/` со ссылками на sha вместо пересказа коммитов; в живой слой из него переносятся только статусы и решения. Оригиналы в `history/` не редактируются.
- Новое обозначение или термин с двумя смыслами — `GLOSSARY.md`.
- Изменил поведение DPoS — обновить `.claude/dpos_architecture/` в том же изменении (правило CLAUDE.md), в живой слой архитектуру не писать.
