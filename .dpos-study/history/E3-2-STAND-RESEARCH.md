## 1. Ответ

[KNOWN] Стенд 3.2 строится на существующих швах **без правок прод-кода** в его базовой форме: N = 4 и N = 8 узлов `OuterBuilder` в одном `deterministic::Runner` поверх одного `commonware_p2p::simulated::Network` собрались, финализировали 6 блоков за 6 виртуальных секунд (1 blk/s, все узлы в lockstep), расходящийся deriver на одном узле был пойман (SafetyHalt на узле 2 по высоте h+K, его предложения отвергнуты остальными), пять границ эпох со сжатием комитета 4→3 прошли (проба §4, файл пробы — 470 строк, пишется как `#[cfg(test)]`-модуль внутри `crates/dpos/consensus`). Три вещи всё же требуют правок прод-кода, все поведенчески нейтральные: (а) виртуальное время под этим крейтом идёт **1:1 с реальным** — `consensus/Cargo.toml:33` включает фичу `external` runtime, которая нужна ради `Pacer`/`FutureExt::pace` (два вызова в `executor.rs:1970,2031`), а под ней deterministic спит 1 мс реального времени на цикл и не пропускает простой (`CW:runtime/src/deterministic.rs:397-404,413-416`); снять это — заменить `Pacer` локальной заглушкой (~1 день); (б) разделы журналов `consensus_epoch_{E}` (`engine.rs:285`) и `dkg_epoch_{E}` (`beacon/dkg_engine.rs:252-254`) не префиксуются по узлу — в одном процессе с общим in-memory Storage N узлов пишут в один раздел (проба прошла, но это [ГИПОТЕЗА]-мина под рестарт/replay; ~0,5 дня); (в) `plane_upstream.rs:280` использует `tokio::time::timeout` — [ГИПОТЕЗА] под deterministic без tokio-рантайма это паника при первом poll, лечится `ctx.sleep` (~0,5 дня). Что стенд **не** сделал в пробе и что составляет основную цену: beacon-плоскость (`beacon::build`, `plane.rs:415`) с живым DKG на N узлах не поднималась — у неё нет ни одного теста (в `plane.rs` нет `mod tests`), хотя её части уже гоняются по 4 узла на simulated (`dkg_engine.rs:1190-1300`, `beacon/actor.rs:2811-2900`); и фейк-стейкинг как машина состояний эпох (вместо моего ретранслятора границ). Оценка — **9–11 дней** (§6), из них [ГИПОТЕЗА] — beacon-плоскость (3 дня) и фейк-стейкинг (2 дня).

## 5. Предлагаемая форма стенда

- Где живёт: `crates/dpos/consensus/src/testbed/` как `#[cfg(test)] mod` (доступ к `StaticRandomness`, `NoopSlasherSink`, `pub(crate)`-типам; при желании — фича `test-support`, чтобы вынести в `crates/dpos/testbed`). Отдельный крейт сейчас невозможен без экспорта `Randomness`-типов (§2 #4).
- API теста:

```rust
let mut stand = Stand::new(StandConfig { n: 4, seed: 7, epoch_len: 32, latency: 10.ms(), loss: 0.0 });
stand.node(2).role(Role::DivergentResult { at: 3 });   // или Equivocate (feature), TwoReveals, FalseLatest…
stand.partition(&[0, 1], &[2, 3]).for_views(5..9);      // oracle.remove_link/add_link
let out = stand.run_until(|s| s.min_height() >= 40 || s.halted().is_some(), 120.s());
assert_eq!(out.diverged, Some(Divergence { node: 2, height: 3, kind: ResultMismatch }));
assert_eq!(out.halted, vec![(2, "result divergence at height 6")]);
out.assert_lockstep_except(&[2]);                        // все остальные — одна цепь
```

- Параметризуется: N, seed (`deterministic::Config::with_seed`, `CW:deterministic.rs:267`), `epoch_len`, `Link{latency,jitter,success_rate}` per-пара, партиции по view/времени, роль узла, комитет по эпохам (снимки), `dkgQual`, наличие upstream.
- Как сообщает о расхождении: (1) скан `spec_executed_hash(h)` по всем узлам после прогона — первая пара (узел, высота) (как в пробе); (2) перехват `LOG ERROR`/`SafetyHalt` через свой `tracing::Subscriber` с меткой узла (в пробе — 25 строк, без `tracing-subscriber`, которого нет в dev-deps); (3) `ctx.encode()` метрики с префиксом `node{i}_…` (счётчики `dpos_marker_reject_total`, `epoch_manager`); (4) по view — из `Activity` через второй `Reporter` в `Reporters::from((app, feed))` (`outer.rs` `feed: Option<FeedSink>`).

## 8. Оставлено как есть — что выглядело препятствием и не оказалось

- `canonical_state: reth_chain_state::CanonicalInMemoryState` в `OuterBuilder` (`outer.rs:650-651`) — прод-тип без трейта, но `CanonicalInMemoryState::empty()` есть (`reth …/crates/chain-state/src/in_memory.rs:210-212`), и он читается только при `last_consensus_finalized_height > dpos_activation_block` (`outer.rs:1016-1023`).
- `tokio::sync::*` и `tokio::select!` — runtime-нейтральны, работают под deterministic (проба).
- `SystemTime`-поля (`artifact.rs:908`, `follower.rs:293`, `executor.rs:559`) — заполняются из `Clock::current()`.
- `simulated` за `stability_mod!(ALPHA)` — доступен в тестах без фич.
- Ловушка «unix-масштабный `sleep_until`» — снимается `genesis.timestamp = 0` или `with_start_time`.
- `SharedMux` — `pub(crate)` алиас (`outer.rs:48`), но `start()` принимает базовый тип `Arc<tokio::sync::Mutex<MuxHandle<HS,HR>>>` — из теста передаётся.
- Метрики `metrics::counter!` (глобальный рекордер) — N узлов в процессе сливают счётчики, но commonware-метрики через `ctx.with_label("node{i}")` разделены (проба: `runtime_task_polls_total{name="node0_…"}`).
- Общий раздел `consensus_epoch_0` у 4–8 узлов — проба прошла (см. §2 #2 — оставлено как мина, не как блокер).
