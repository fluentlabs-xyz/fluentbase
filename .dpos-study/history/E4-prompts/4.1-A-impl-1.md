### А1. Модуль `committee/`

Форма — §5.1 проекта, с одним переименованием: имя трейта `CommitteeReads` занято (`beacon/plane.rs:108`), поэтому трейт модуля называется **`committee::Committee`** (форма API из строки 4.1: `{committee, changed, is_member, subscribe}`), продакшн-реализация — **`committee::CommitteeStore<R: StakingStateRead>`** (имя можно уточнить, но записать в журнал).

~~~rust
pub struct CommitteeRecord {
    pub epoch: u64,
    pub members: Vec<Member>,      // порядок — как вернул контракт (reader никогда не сортирует)
    pub weights: Vec<u128>,        // ОБЯЗАТЕЛЬНЫ: weights: None в окне ⇒ CommitteeError::Read(permanent)
    pub changed: bool,             // getDkgQual(epoch) — ВТОРОЙ staticcall на ТОМ ЖЕ хэше
    pub snapshot: (u64, B256),     // (block_number, block_hash) снимка — диагностика
    // производные, один раз из members: bimap/participants — как удобно потребителям (EpochCommittee из scheme.rs / commonware Set)
}
pub struct Member { pub address: Address, pub peer: PeerPubkey, pub bls: BlsPubkey }  // tombstoned — НЕ здесь; activation_epoch — не переносится
pub enum CommitteeError {
    NotReadable { epoch: u64, ready_at: u64 },   // anchor < commit_height(E) ИЛИ якорь не исполнен — БЕЗ EVM
    OutOfWindow { epoch: u64, lo: u64, hi: u64 }, // вне [epoch(anchor) − SCHEME_RETENTION_EPOCHS, epoch(anchor) + MAX_COMMITTEE_LOOKAHEAD_EPOCHS] — БЕЗ EVM
    Read(ReadError),                              // с ReadError::is_transient(): StateNotMaterialized | TransientStorage | BlockNotFound ⇒ transient; остальное — permanent
}
pub trait Committee: Send + Sync {
    fn committee(&self, epoch: u64) -> Result<Arc<CommitteeRecord>, CommitteeError>;
    fn changed(&self, epoch: u64) -> Result<bool, CommitteeError>;
    fn is_member(&self, epoch: u64, peer: &PeerPubkey) -> Result<bool, CommitteeError>;
    fn subscribe(&self) -> tokio::sync::watch::Receiver<u64>;   // «наивысшая читаемая эпоха выросла»
}
~~~

Семантика `CommitteeStore` (всё — §5.1 «Якорь», «Инвариант окна», «Кэш и ретенция», «Единый тип ошибки»):

- **Якорь** — `executed_state_hash(anchor_height)` (`executed.rs:49-58`), где `anchor_height` = локальный ordering-финализированный tip. Источник высоты — на твой выбор из двух, записать в журнал какой и почему: (а) `FinalizedCursor` (`application.rs:151`) — тот же монотонный курсор, что `ordering_finalized` (`executor.rs:1149/2441/3291` против `advance_finalized` `:1085/2451/3566` — проверь сам, что точки записи совпадают, и запиши якоря), плюс геттер высоты; (б) собственный `watch`/атомик в модуле, который заход Б будет двигать из executor'а в тех же трёх точках. Предпочтение — (а), если точки совпадают: один курсор вместо второго. В заходе А модуль получает источник как параметр конструктора; executor не трогается.
- **Геометрия** `(activation, interval)` — параметр конструктора (заход Б возьмёт её из `EpochTransition::frozen_geometry()`); `epoch_of(height)` — `staking_protocol::epoch_at_block` (`crates/types/src/staking_protocol.rs:118`), ту же формулу использует `FakeStaking::committed_at` (`fakes.rs:966`). `start(E)` и `last(E)` — по той же геометрии.
- **`commit_height(E)`** = `start(E − MAX_COMMITTEE_LOOKAHEAD_EPOCHS)`; для `E ≤ 2` — блок **1**, не 0 (PRECONDITIONS §7: бутстрап коммитит только эпоху 0, а первый исполненный блок коммитит 1 и 2). Если `anchor_height < commit_height(E)` ⇒ `NotReadable{ready_at: commit_height(E)}` **без единого вызова reader'а**. Если `executed_state_hash` вернул `Ok(None)` ⇒ тоже `NotReadable` (якорь не исполнен). `Err` пробы ⇒ `Read(Backend)` (permanent — см. `executed.rs` док: miss на исполненной высоте — не транзиент).
- **Окно**: `E ∈ [epoch(anchor) − SCHEME_RETENTION_EPOCHS, epoch(anchor) + MAX_COMMITTEE_LOOKAHEAD_EPOCHS]`, иначе `OutOfWindow` без EVM. Порядок проверок: окно → readable → кэш → EVM.
- **Чтение**: ровно один `epoch_committee_snapshot(E, anchor_hash)` + один `dkg_qual(E, anchor_hash)` на тот же хэш (два staticcall). Пустой `validators` ⇒ `NotReadable` (никогда `Permanent` — E4-25). `weights: None` ⇒ `Read(permanent)` с `error!` (контракт отдал невозможное в окне). Ошибки reader'а — через `is_transient()`: транзиент ⇒ `Read(transient)` без записи в кэш; постоянная ⇒ `Read(permanent)` + `error!` один раз на эпоху (без спама на каждый вызов — записать, как ограничил).
- **Кэш write-once**: `BTreeMap<u64, EpochEntry>`; `EpochEntry` сейчас держит `Arc<CommitteeRecord>` и оставляет место для `scheme` (заход Б делает `EpochSchemeProvider` видом на эту карту — спроектируй `EpochEntry` так, чтобы Б добавил слот схемы без переделки; но в А слот не добавляй). Повторное чтение той же эпохи с другим значением (состав/ключи/веса/бит) ⇒ `error!` и отказ эпохи (`Read(permanent)`), существующая запись сохраняется; без `debug_assert`. Ретенция — `pop_first` до `SCHEME_RETENTION_EPOCHS` записей (как `outer.rs:373-375`).
- **`subscribe`**: `watch::Receiver<u64>` наивысшей читаемой эпохи (`epoch(anchor) + MAX_COMMITTEE_LOOKAHEAD_EPOCHS`), обновляется, когда модуль узнаёт о росте якоря. Как модуль узнаёт — от источника высоты (если (а) — `FinalizedCursor` не будит; тогда модулю нужен явный `notify_anchor(height)`/`advance(height)`, который Б вызовет из executor'а; запиши выбор). Дизайн должен быть событийным, не таймерным.
- **`is_member`** — по `members` записи; `tombstoned` не участвует (RULE 37, проект §5.1 «tombstoned»).
- Все методы синхронные (reth-чтения блокирующие, как в сегодняшнем `CommitteeReads`).
