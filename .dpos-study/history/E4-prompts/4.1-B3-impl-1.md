### Б3.1. `FakeStaking` — состав по ветке хэша, кольцо весов, тумбстоуны

- **Состав по ветке хэша.** Сегодня `members: Fn(epoch) -> Option<Vec<usize>>` — чистая функция эпохи (`fakes.rs:844`), `at` решает только «закоммичено ли». Добавь необязательную ветвящую схему: `StandConfig` получает `committees_by_branch: Option<Arc<dyn Fn(epoch, &B256 /* at */, height) -> Option<Vec<usize>>>>` (или расширение `Committees`), по умолчанию `None` = сегодняшнее поведение; продакшн-путь стенда не меняется.
- **Модель кольца.** `weights: None` для эпох `epoch ≤ current(at) + MAX_COMMITTEE_LOOKAHEAD_EPOCHS − WEIGHT_RING_EPOCHS` (константы из `fluentbase_types::staking_protocol`), иначе `Some(vec![1; n])` как сейчас. Плюс переключатель для теста «weights: None в окне» — например `StandConfig::weights_none_for: Option<u64>` (эпоха, для которой фейк отдаёт `None` несмотря на окно — «контракт отдал невозможное»).

- `StakingReads` — добавить счётчик `weights_none: BTreeMap<u64, u64>` и `tombstoned_seen` (что-то наблюдаемое), если тестам нужно.

### Б3.2. Три стенд-теста (форма — как `testbed/preconditions.rs`: сначала посылка, потом свойство; имена — предложения)

1. **«Два узла на разных высотах — одна запись»** над ВЕТВЯЩИМСЯ фейком: 4 узла, один отстаёт (например, `Role`/линк с задержкой или ранний `stop` одного узла и догон), фейк на неканонической ветке (хэш, который узел видит только спекулятивно) отдаёт ДРУГОЙ состав для эпохи `E+1` — а на канонической ветке одинаковый. Утверждение: у всех узлов запись `committee(E+1)` (участники, веса, бит) побайтно одна и совпадает с канонической; ни один узел не прочитал `E+1` на неканоническом хэше (`StakingReads` по хэшу или счётчик «чтений на спекулятивной ветке» — добавить наблюдаемость в фейк); посылка: спекулятивная ветка на каком-то узле реально существовала (`el_events`/`head_gap_on_fcu` из предусловий). Над сегодняшним фейком тест был бы тавтологией — это и надо показать в журнале: назвать, какой ассерт был бы истинен вакуумно без ветвления.
2. **«На бэкфилле `NotReadable` без EVM»**: узел, догоняющий через plane/backfill (есть фикстура — `testbed/tests.rs` «догон через plane», или гейт `re_jump_threshold`), в момент, когда его якорь ниже `commit_height(E)`: `StakingReads.uncommitted` для `E` НЕ растёт (чтения не было), а метрика `dpos_committee_not_readable_total` (текст метрик `Outcome::metrics`) растёт; после догона запись появляется и `committed[E] == 1` (один снимок на эпоху). Посылка: узел действительно был ниже `commit_height(E)` в момент запроса (докажи через `Outcome`).
3. **«`weights: None` в окне ⇒ `Read(permanent)`, verifier не строится, ошибка громкая»**: `weights_none_for = Some(E)` для эпохи внутри окна; утверждение: у каждого узла `dpos_committee_read_permanent_total{reason="weights_none"} ≥ 1`, схема/запись эпохи `E` в модуле НЕ появилась (наблюдай через фасад или счётчик `committed[E]` + отсутствие `Verifier`-регистрации — что доступно из `Outcome`), в логах-капче есть `error!` про permanent (`capture` модуль стенда) ровно один раз на узел; остальная цепь до `E` жива. Посылка: эпоха `E` действительно внутри окна модуля в момент чтения.

Каждому тесту — «был ли красным до правки» невозможен буквально (тест новый), поэтому — мутация фейка/продакшн-предиката (например, снять ветвление ⇒ тест 1 обязан стать вакуумно зелёным — ЗАПИСАТЬ, что именно поймал бы тест и что нет; для теста 2 — заставить фейк читать при `NotReadable` нельзя без продакшн-правки — утверждай через счётчики, а мутацию опиши как «если бы модуль читал до `commit_height`, `uncommitted[E]` стал бы > 0» и проверь это, временно выставив якорь стенда выше (только в тестовой конфигурации)).

### Б3.3. e2e-пин `commit_height(E) = start(E−2)` на rWasm

В `e2e/` (реальный rWasm-блоб стейкинга, `EvmTestingContext`, `set_block`): при `set_block(h)` с `epoch(h) = c` вызов `commitEpochCommittee` для `c + 2` проходит и `getEpochCommittee(c+2)` непуст, для `c + 3` — ревёрт; и для `c ≥ 1`: на блоке `start(c)` — `c+2` проходит, на блоке `start(c) − 1` — ревёрт (граница ровно на первом блоке). Для `E ≤ 2` — оба коммитятся на блоке 1 (после генезисной эпохи 0). Имя — предложение; ассерты на статус вызова и на непустой ответ; проверь ДО написания, что e2e-контекст умеет ревёрт различать (посмотри, как `staking_cost.rs`/`staking.rs` проверяют ошибки). Запусти `cargo test -p fluentbase-e2e --release <имя>` (крейт тяжёлый; только свой тест по фильтру; в журнал — verbatim). Если e2e-контекст не позволяет (нет способа выставить регистр валидаторов ≥ 4 без большого фикстурного кода — посмотри, есть ли готовый хелпер в `staking.rs`), запиши в §7 с якорем, что именно недоступно, и пин сделай на уровне `crates/node/src/evm.rs` тестов `drive_ahead_commit` — но только если это разрешено (файл вне списка — тогда только записать).
