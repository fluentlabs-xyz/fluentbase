## 2. Answers to the eight questions

**(1) FINALIZE and the ADOPT GATE (R-039/F-02).**
Both `adopt_share` paths validate against the ARTIFACT: live at `actor.rs:2356` with `set.group_key.clone()`, where `set: AgreedSet` came from `apply_artifact(epoch, &proposal)` (`:1416`) and `AgreedSet::of(proposal)` (`:244-252`); heal at `actor.rs:3337` with `st.outcome`, set in `heal_over` from the same `set.group_key` (`:2431-2436`). The `DkgProposal` provenance is the `AgreedOutcomeAt` read handle (`:202-203`), wired in `plane.rs:794-800` to `store.get(epoch).map(|a| a.0.clone())`, i.e. the `ArtifactStore` populated only after `verify_artifact_for_epoch` (`artifact.rs:1549-1611`) or after the instance's own certified `resolve_artifact` (`dkg_engine.rs:384-451`). The live path's local `_out` is bound with an underscore (`:2348`) and is unused; grep shows only the two call sites, so the local outcome cannot reach `adopt_share`. On `Refused`: `OffPolynomial` → counter + unlatched ERROR, no store insert, state `Acquiring(Logs)` (`:2365-2370` live / stays `:3339-3349` heal), journal retained; `PersistFailed` → same state + `Stalled{PersistFailed}` (`:2366-2369`, `:3346-3348`). **However**, the `Acquiring(ArtifactForShare) → Keyed` (`:1480-1482`) and `recover` share+artifact (`:2586-2595`) transitions put a disk-loaded share into `Keyed` with no polynomial check — DB-01.

**(2) RECOMPUTE/HEAL.** `Acquiring(Logs)` is driven by `drive_acquisition` (`:3243`) → `try_recompute` (`:3275-3372`). Exits: `Ok`+adopt → `Keyed` (`:3365`); `Err(MissingPlayerDealing)` → `Unrecoverable` (`:3329`); every other `Err`, an `adopt_share` refusal, or `NoFile/Torn` journal → stays (`:3296-3298`, `:3333`, `:3346-3349`). It no longer requires `now == E` (no clock in `try_recompute`; `fetch_missing_logs` drives `st.want` regardless of boundary, `:3127`), fixing T8/E5-11. It can still spin every tick when `want` is empty and the journal keeps producing a retryable error/refusal — R-038 is explicitly out of scope, but the live path now feeds the same loop (DB-03). It also no longer early-returns on `share_dir`/`outcome_at` absence the way HEAD's `drive_recompute` did; without a journal it just `continue`s.

**(3) SWEEP and RETENTION.** One predicate, `retained(e) = e + R >= now` (`:1767`); slots removed there (`:1769-1782`), gauges stepped down per latched reason (`:1777-1779`). Compared with HEAD: `ceremonies`/`recompute_pending`/`agreed_pinned`/`terminal_recompute`/`equivocations`/`deferred_reported`/`eval_logged`/`torn_warned` all used the same predicate, so keyed shares in `store` (unchanged `ceremony_retain_floor`), evidence, nondurable logs and terminals are swept on the same window. Two differences: (a) terminal slots (`SatOut`/`Unrecoverable`/`Conflict`) now contribute their journals to `evictable`, so those journals are reclaimed at age-out whereas HEAD's `evictable` (`log_store ∪ ceremonies ∪ recompute_pending`) did not include `torn_warned`/`terminal_recompute`-only epochs — a retention FIX (earlier reclaim); (b) `announced` now lives as long as the slot instead of as long as the ceremony (DB-05, unobservable). Gauges go down on `Keyed` (`:1274-1278`) and on the sweep; the exception is a non-`Keyed` resolution (`KeyOnly{Some}` etc.) — DB-06.

**(4) CEREMONY CHANGES.** `resume(.., preferred)`: the preferred body is used only when its hash is in the journal (`file_log`, `ceremony.rs:969-975`); the actor passes `pinned_by_dealer(&next, &set.pinned)` only when the artifact is held (`actor.rs:2749-2754`), else an empty map → first-recorded. `finalize_over_pinned` still selects by pinned hash (`scoped_pinned_logs`, `ceremony.rs:1179-1209`), so the preference is not defeated by `signed_logs`. `withhold_ack`: durable-before-ack is traced on the live path (`actor.rs:2976`, `:2988-2999`) and the drain (`:2522-2529`); a withheld ack cannot be re-emitted later without a durable journal because `try_ack`'s cache is removed and the replay branch keys off `emitted_acks` (`ceremony.rs:646-655`), which `resume` rebuilds only from journal `ReceivedDealing` records (`ceremony.rs:1059-1065`). `acked_dealers` (`actor.rs:537-545`) reads `Target::Direct + DkgBody::Ack`, which is exactly how `try_ack` emits acks (`ceremony.rs:632-653`). Lifecycle: cached on first receipt, removed on withhold, rebuilt on resume; a failed `ReceivedDealing` write is never retried (DB-08).
