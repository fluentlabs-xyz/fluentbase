**R-001. Прыжок cold-start/re-jump синхронизирует reth к неаутентифицированному хэшу, а комитет для проверки читается из уже синхронизированного состояния.**

Входы: `dpos.rs:1795-1878` (cold start валидатора, L1 = `None` на `:1839`), `:2458-2553` (re-jump, L1 = `None` на `:2524`), `executor.rs:2160-2207` (`maybe_re_jump`), `plane_upstream.rs:198-212` (`deliver` принимает любую декодируемую пару), `:270-310` (`fetch_one`: `FrontierKey::Latest` — резолвер сам выбирает пира из отслеживаемого набора). Отслеживаемый набор = реестр ∪ `committee[e]` ∪ `committee[e+1]` (`staking-reader/src/epoch_transition.rs:614-648`), до 4096 (`p2p/src/constants.rs:186`).
- Механизм: любой отслеживаемый пир отвечает на `Latest` парой `(finalization, block)`, где `payload == block.digest()`, `block.height > anchor + threshold`, `block.result` — хэш его собственной EVM-ветки с подменённым стейкинг-состоянием. Узел даёт reth FCU на этот хэш, reth скачивает ветку по devp2p и финализирует её (эксперимент AUDIT A-1, п. 3), после чего `verify_jump_authenticated` читает `committee[E]` из подменённого состояния и проверка проходит. Эпоха раунда сертификата не сверяется с `epoch_of(block.height)`.
- Последствие: (а) узел живёт на чужой цепи, RPC отдаёт чужое состояние, валидатор перестаёт участвовать; (б) если атакующий сохранил настоящий комитет — через K блоков `ResultDivergence` → `SafetyHalt` с маркером на диске (`executor.rs:3215-3234`), узел выключен до ручного вмешательства; (в) даже при `AuthFailed` reth уже получил `finalized` на чужой хэш и начал pipeline-backfill к нему, обратный FCU reth отклоняет; узел ротирует upstream и повторяет прыжок (`dpos.rs:1296-1311`), но EL остаётся с чужим finalized-указателем (это C-08).
- Тег: **BLOCKER**. Прежние: AUDIT A-1 CRITICAL, CORE C-01 CRITICAL, CORE C-08 MEDIUM. C-08 объединён сюда: тот же код (`sync_to` до аутентификации, `:470-474`), тот же пропуск проверки; его последствие — пункт (в).
- Уверенность: `[KNOWN]` порядок вызовов, чтение комитета при `landing_hash`, отсутствие L1 на валидаторе, `deliver`/`fetch_one`. Эксперимент AUDIT A-1 (reth финализирует названный хэш после devp2p-доставки) — `[LIKELY]`, в сессии не повторялся.

Пункты (а) и (б) не затронуты, тяжесть BLOCKER не меняется.

Ломается СНАБЖЕНИЕ: слой вокруг не может изготовить следующий замороженный комитет и превращает отказ в фатальную ошибку. Это дефект реализации и контракта ВНУТРИ допущений модели. Следовательно бюджет `f` к этой записи неприменим.
- Требования: **атакующего нет — это не атака.** Нужно, чтобы число селекционно-видимых валидаторов дошло до 3. Это `V − 3` выходов, где `V` — текущая видимая популяция; каждый выход — легитимное, индивидуально валидное действие владельца своим ключом, без координации, без стейк-порога (снят явно), без срока уведомления, без требования замены и без лимита на эпоху (проверено `grep`: ни очереди выходов, ни churn-лимита в коде нет). Сериализации нет, поэтому популяция может перескочить безопасный размер 4 (с 6 сразу на 3). Роковой шаг — снятие, уводящее с 4 на 3, — **не отвергается и не предупреждает: транзакция возвращает `status 1 (success)`**, а сеть умирает на следующей границе эпохи. Третьей стороны нет: `full_owner_exit` требует `delegator == owner` (`staking.rs:1228-1230`), селекция фильтрует по штампу, а не по стейку, ключи пишутся один раз.

Порог достигается убылью, а не атакой; последний шаг всегда — одно ничем не ограниченное действие одного участника, и по шкале реестра это «сеть останавливается действиями одного участника». **R-120. Эквивокация в последних видах эпохи при нулевом пересечении комитетов остаётся безнаказанной — ПРИНЯТО как остаточный риск (решение Д-4, 2026-09-04).**
- Код: `application.rs:626-633` (`next_charge(round.epoch())` — заряд предлагается только для эпохи текущего раунда), `slasher/evidence.rs:143-149` (гейт голосования требует `charged == epoch блока`), `slasher/actor.rs:1069-1071` (курсор двигают только активности собственного движка), `:1105-1116` (`republish` вызывается только по `Nullification`/`Notarization`, то есть внутри эпохи), `outer.rs:1209` против `:1231` (слэшер строится один раз на процесс, движки — по эпохам), `slasher/actor.rs:294-303`, `:599-609` (заряд и голоса переживают границу), `slasher/tombstone.rs:11-25` + `application.rs:839` (весь хвост реакции висит на он-чейн флаге `tombstoned`).
- Механизм: заряд эпохи E может попасть в блок только пока идёт E. Ротированный из комитета узел заряд сохраняет, но предложить его не может (нет слота лидера) и его курсор замерз на E. Узел, у которого слот в E+1 есть, заряда не держит: он не был в комитете E, а после конца E улики эпохи E никто не переиздаёт. При нулевом пересечении комитетов (принято как проектное допущение) эти два множества не пересекаются, поэтому эквивокация, замеченная в последних видах эпохи, до контракта не доходит ни одним путём, кроме маршрута по уликам.
- Последствие: эквивокатор не получает tombstone, а значит не срабатывает ничего из зависящего от флага — ни отказ привязывать его предложение, ни разрыв транспорта, ни конфискация самостейка. Он остаётся в комитете со своим весом.
- Почему принято: в пределах BFT-границы цена одного такого эпизода — непрошедший view (нотаризация без финализации), а не остановка цепи. Оценка «в худшем случае nullify» взята из памяти проекта (`dpos-asymmetric-equivocation-zero-finalize-margin`) и в этой сессии не перепроверялась — `[LIKELY]`.
- **Что оценка «вероятность мала» НЕ покрывает** (проверено в этой сессии, `[KNOWN]`): эквивокирует ГОЛОСУЮЩИЙ, а не лидер — `VoteEquivocator` двойно подписывает каждый Notarize/Finalize, который узел и так бы отдал, добавляя случайное предложение (`byzantine.rs:52-58`, `:101-108`). Быть избранным лидером для этого не нужно, значит атакующий выбирает view свободно, в том числе последний в эпохе. А поскольку наказание не приходит, приём повторяем на каждой границе эпохи неограниченно. То есть это не редкая случайность, а дешёвый и повторяемый налог на живучесть у границ, ограниченный только BFT-порогом. Малой является вероятность СЛУЧАЙНОГО попадания в это окно, не вероятность намеренного.
- Тег: **ПРИНЯТО** (остаточный риск, не задача). Прежде не фиксировалось ни одной записью.
- Уверенность: `[KNOWN]` по механизму недоставки — все шесть якорей прочитаны; `[LIKELY]` по характеру последствия (см. выше).
- Что сняло бы: маршрут по уликам (границ эпох не замечает — контракт держит комитеты всех эпох вечно, `storage.rs:217-222`), либо переиздание улик через границу плюс приём их новым комитетом. Цена обоих — `DECISIONS.md`, раздел Д-4.
- Связано с: R-022, R-028, R-116; `DECISIONS.md` Д-4.

## Часть 2. Порядок работ

Три ограничения задают порядок. Первое: ничто в executor и beacon нельзя перестраивать, пока σ приходит по четырём путям, потому что каждую правку исполнения нужно доказывать на одном источнике σ (AUDIT B-1 раньше B-8, B-6, B-7).
